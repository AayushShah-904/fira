WHAT WAS DONE
-------------

The refresh pipeline (scripts/refresh/) ran end-to-end with sanity gating and
LLM verification, then promoted the verified subset into output/latest/ and
rebuilt the rates pack.

Pipeline order:
  1. build-cohort.js    — walked output/latest/, grouped per-bank rate variants
  2. detect-changes.js  — one HTTP GET per (bank, variant) URL, cached bodies,
                          classified each pair by signal (effective_date,
                          content hash, PDF byte hash, Last-Modified)
  3. extract-and-diff.js — deterministic extraction from cached bodies
                            (no re-fetch) + slab-level diff vs current
  4. sanity-gate.js     — flagged candidates with implausible moves: >75bps
                          single-slab delta, gen==sr collapse, all-senior-null,
                          rate <1% or >9.5% on INR variants, slab-count drift
                          >50%
  5. verify-with-llm.js — for each flagged candidate, gpt-4.1-mini re-extracted
                           from the SAME cached body, then re-ran sanity gate
                           against the LLM output to catch structurally weird
                           pages where the LLM also can't disambiguate columns
                           (e.g., PNB's "Existing vs Revised" comparison view)
  6. promote.js --apply — wrote only verified candidates through safeWriteArtifact;
                           the curated-data check (ADR-012) routes operator data
                           to *.pending.json instead of overwriting
  7. report.js          — final report.txt + summary.txt + report.json
  8. pack/build-pack.js — refreshed pack/dist/rates-pack.json for PM's UI

WHAT WAS NOT PROMOTED (BY DESIGN)
---------------------------------

  llm_still_suspicious  48
  llm_rejected           9
  llm_no_data            1
  ... and from the original 175 suspicious, those whose sanity flag was
  zero-slab (30) ended up in extraction_failed.

  By bank_type:
    PVB 13  PSB 12  SUCB  7  FB  7  RRB  5  SFB  5
    IBU  3  DCCB  3  SSCB  2  NSSCB 1

The held-back PSB list includes Punjab National Bank's regular and FCNR
variants — root cause: PNB's rate page uses a 4-column "Existing vs Revised"
layout with no proper senior column, which neither deterministic nor LLM
extraction can reliably parse without a bank-specific rule.

65 extraction-failed (zero slabs):
  - 30 of these were also flagged by sanity gate; LLM SKIPPED them (no usable body)
  - 35 deterministic returned 0 slabs and weren't suspicious because there was
    nothing to be suspicious about
  Existing output/latest/ rates preserved untouched for all 65.

97 unreachable:
  - 42 no_source_url   (banks we never had a URL for; mostly DCCBs and edge FBs)
  - 36 fetch_failed    (network errors / DNS — small cooperative banks)
  - 12 http_404        (rate page URL went stale; bank moved it)
  -  4 http_307        (redirect loops; need follow-up)
  -  1 http_403, 1 http_410, 1 timeout

FOLLOW-UPS THAT BELONG IN A SPRINT, NOT THIS RUN
------------------------------------------------

- LLM verification could lean on the deterministic candidate as a hint
  in the prompt — "the simple extractor read these values; do you agree,
  and if not, what did it get wrong?" This would help cases where the
  LLM hallucinated common short-end rates instead of reading the actual
  table.

- A second-pass loop after held-back triage: once an operator fixes
  PNB-style configs, the pipeline should re-run extract-and-diff only on
  those banks (--slug filter already supports this) without re-fetching.

- The held-back-and-promoted accounting could move into a single
  _refresh_status.json so future runs can do a fast "what changed since
  last refresh" without re-walking the diffs directory.

- A small UI to flip a held_back -> promoted decision per bank would
  speed up the manual review step.
