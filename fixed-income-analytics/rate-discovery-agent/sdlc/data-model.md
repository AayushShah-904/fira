# Data model

This document describes the durable data the agent reads, writes, and publishes. File-level schemas are normative — the agent's `CLAUDE.md` and `lib/` validators enforce them. Storage layout (filesystem in local mode, blob containers in containerized mode) is normative for sprint 001 onwards per [ADR-010](decisions/ADR-010-blob-layout.md).

## File schemas (canonical)

The schemas below already exist in code; they are documented here for reference. The authoritative copy of each schema lives in:

- Bank discovery output: agent's `CLAUDE.md` (rate file schema, config file schema)
- Domain registry: `data/bank-domains.json` (self-describing)
- Pack bundle: `pack/dist/rates-pack.schema.json` (JSON Schema, generated by `pack/build-pack.js`)

### `data/bank-domains.json`

Map of bank slug → entry. Persistent across runs; updated when a new bank is discovered or a manual correction is applied.

```jsonc
{
  "<bank-slug>": {
    "domain": "bank.bank.in",                 // bare hostname, no scheme
    "domain_source": "discovered" | "manual" | "probed",
    "status": null | "wholesale_only" | "rates_not_published" | ... ,
    "rate_pages": {
      "fd": "/interest-rates" | null,
      "fd_nre": "/nri/nre" | null,
      "fd_nro": "/nri/nro" | null,
      "fd_fcnr": "/nri/fcnr" | null,
      "fd_nri_combined": "/nri/deposits" | null,
      "savings": "/savings-rates" | null,
      "rd": "/recurring-deposits" | null
    },
    "scraper_type": "html_static" | "html_js" | "pdf" | "mixed" | "manual",
    "parent_bank_code": null | "<parent-slug>",   // for IBU banks
    "scraper_notes": { ... },
    "notes": "free-form prose"
  }
}
```

Status taxonomy is documented in `docs/status-taxonomy.md`.

### `<bank-slug>_config.json`

Per-bank configuration written by the agent during discovery. Stable across rate refreshes; only updated when the bank's website structure changes. Schema matches the Config File Schema in `CLAUDE.md`.

### `<bank-slug>_rates.json` (and variants)

Per-bank, per-variant rate data. Refreshed every run. Variants:

| Suffix | `variant` field | Currency dimension |
|---|---|---|
| `_rates.json` | `regular` | INR (implicit) |
| `_nre_rates.json` | `nre` | INR (implicit) |
| `_nro_rates.json` | `nro` | INR (implicit) |
| `_fcnr_rates.json` | `fcnr` | per-slab `currency` field, e.g. `USD`, `GBP` |
| `_gift_rates.json` | `gift` | per-slab `currency` field |

Schema matches the Rate File Schema in `CLAUDE.md`. Field-name discipline (`tenure_min_days` not `min_days`, `rate_slabs` not `slabs`, `scraped_at` not `extracted_at`) is enforced by `lib/validators/`.

### `<bank-slug>.summary.json`

Per-run telemetry: cost, token counts, tool-call counts, model used, runtime. Useful for cost tracking and debugging. Not consumed by the pack.

### `<bank-slug>.log`

Plain-text agent log for the run. Not consumed by anything; kept for debugging.

### `pack/dist/rates-pack.json`

Denormalized bundle assembled from all `*_config.json` and `*_rates.json` files. Schema is generated alongside as `rates-pack.schema.json` and described in `pack/dist/README.md`. Top-level shape:

```jsonc
{
  "pack_version": "1.0.0",
  "generated_at": "<ISO-8601 UTC>",
  "enums": { "bank_types": [...], "variants": [...], "statuses": [...], ... },
  "counts": { "banks_total": N, "banks_with_regular_fd": N, ... },
  "banks": [
    {
      "bank_code": "<slug>",
      "config": { ... },
      "rates": {
        "regular": { ... } | null,
        "nre": { ... } | null,
        "nro": { ... } | null,
        "fcnr": { ... } | null,
        "gift": { ... } | null
      }
    }
  ]
}
```

The pack is regenerated end-to-end on every publish — there is no incremental update path. Banks with no extracted rates appear in `banks` with all `rates` slots `null` so the consumer can tell "we tried" from "we never heard of this bank."

## Storage layout

### Local development (filesystem)

Paths are relative to the repo root.

```
rate-discovery-agent/
├── data/
│   └── bank-domains.json
├── output/
│   └── latest/
│       ├── _bank_index.json
│       ├── <slug>_config.json
│       ├── <slug>_rates.json
│       ├── <slug>_<variant>_rates.json
│       ├── <slug>.summary.json
│       ├── <slug>.log
│       └── legacy/              ← older-convention files preserved
└── pack/
    └── dist/
        ├── rates-pack.json
        ├── rates-pack.schema.json
        └── README.md
```

### Containerized (Azure Blob Storage)

Single storage account, two containers — see [ADR-010](decisions/ADR-010-blob-layout.md):

#### Container `agent-state` (private, R/W by Container App managed identity)

Mirrors the local layout, with the repo root as the implicit prefix:

```
agent-state/
├── data/
│   └── bank-domains.json
├── output/
│   └── latest/
│       ├── _bank_index.json
│       ├── <slug>_config.json
│       ├── <slug>_rates.json
│       └── ...
└── runs/                        ← per-run logs and summaries (containerized only)
    └── <ISO-8601-timestamp>/
        ├── <slug>.log
        └── <slug>.summary.json
```

The `runs/` separation (vs. local's `output/latest/<slug>.log`) avoids the per-run log files clobbering each other in concurrent batch runs. The storage adapter handles this transparently — local mode keeps logs in `output/latest/` for debugging convenience.

#### Container `rates-pack` (private, read by PM's service principal)

```
rates-pack/
├── rates-pack.json
├── rates-pack.schema.json
└── README.md
```

Always overwritten on publish. No versioning in sprint 001 — versioning by date suffix is a candidate for a later sprint if PM needs historical packs.

## Storage adapter key conventions

The storage adapter interface uses **forward-slash-separated string keys**, matching blob conventions. Local mode resolves the key relative to the repo root.

Examples:

| Operation | Local fs path resolved | Blob key in `agent-state` |
|---|---|---|
| `readJson("data/bank-domains.json")` | `<repo>/data/bank-domains.json` | `data/bank-domains.json` |
| `writeJson("output/latest/hdfc-bank-limited_rates.json", d)` | `<repo>/output/latest/hdfc-bank-limited_rates.json` | `output/latest/hdfc-bank-limited_rates.json` |
| `list("output/latest/")` | `readdirSync("<repo>/output/latest")` | blob `listBlobsFlat` with prefix |

## Concurrency and consistency

Last-writer-wins at the file level — see [ADR-010](decisions/ADR-010-blob-layout.md). Agent runs are **append-or-overwrite** at the file level; there is no record-level merging. Two runs targeting the same bank simultaneously will race and the last writer wins. This is acceptable because:

- Manual triggers are operator-driven and serialized in practice.
- Scheduled runs (sprint 002) will be tier-batched, not per-bank, so there is no overlap by design.
- The pack is regenerated end-to-end on each publish, so a partial mid-batch publish is internally consistent (just stale on the banks not yet processed).

Blob storage's "last writer wins" semantics match this model. No conditional writes, no etag handling required in sprint 001.

## What is not in the data model (yet)

- **Historical rate snapshots.** Rates published change over time, but only the latest is kept. The BIRD database is the system of record for history (it has versioning columns).
- **Audit trail of who ran what when.** `*.summary.json` captures per-run metadata but there is no aggregated runs index. Deferred to sprint 003 (observability).
- **Rate-pack versioning.** Each publish overwrites. If PM ever needs historical packs, add `rates-pack/<date>/rates-pack.json` alongside the latest copy.
