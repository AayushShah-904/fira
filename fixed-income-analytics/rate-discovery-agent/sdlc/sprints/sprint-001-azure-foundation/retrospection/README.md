# Sprint 001 — Retrospection

Written at sprint close. Expected contents:

- `retro.md` — single document covering:
  - **What worked** — decisions or practices to keep
  - **What didn't** — friction points, miscalibrations, surprises
  - **What to change** — concrete changes for sprint 002 (process, tooling, scope sizing)
  - **Estimate accuracy** — actual vs. estimated effort per workstream from `plan/scope.md`
  - **Deferred items status** — which deferred items had their revisit conditions triggered during the sprint, which still hold

Retrospection is the input that makes future sprint planning sharper. Be honest, especially about what didn't work — that's where the value is.
