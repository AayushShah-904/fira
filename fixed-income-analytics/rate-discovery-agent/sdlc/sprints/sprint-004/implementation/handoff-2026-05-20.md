## What NOT to do (lessons from prior cloud incidents)

- Do NOT run `iac/deploy-image.sh` — that re-applies Bicep, which the operator wants to avoid this iteration.
- Do NOT use `start-cohort.js --cohort` — passes `--cohort=<name>` to the container but `run-batch.js` has no `--cohort` mode, so the slugs never get loaded.
- Do NOT trust `az acr build` exit code in isolation — Sprint 1 saw the build complete on Azure but CLI lost the response (network RST). Always re-verify with `az acr repository show-tags`.
- Do NOT use `--replace-env-vars` on `containerapp job update` — it wipes AZURE_STORAGE_ACCOUNT_NAME / AZURE_OPENAI_* and breaks the next run.
- Do NOT declare success on "blob exists" — Sprint 3 lost $64 because pull-mutate-push left stale blobs that LOOKED fresh. Always check `lastModified` advanced.
- Do NOT trigger via the Function App layer — Sprint 2 retro called it unnecessary; direct `az containerapp job start` is the supported path.
